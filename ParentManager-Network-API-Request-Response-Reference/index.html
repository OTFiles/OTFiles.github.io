家长管理 6.2.8 全部网络接口：请求/响应格式速查手册（防厂商跑路存档）

目的：把 6.2.8 中所有网络请求的 URL、请求参数、响应 JSON 结构 完整存档。
万一厂商倒闭/服务器关闭，这份文档足够让我们自己模拟服务端、或理解设备行为、或搭建本地替代服务器。
来源：家长管理_v6.2.8.apk 反编译逐行提取，全部为实测代码，非推测。

🔄 2026-08 修正版：根据真实抓包 + 逆向对照修正了 jpush/content 响应结构（字段在 data 内）、control_list 字段名、status=2 映射、签名秒/毫秒单位、空 control_list 陷阱等关键差异。

〇、公共约定（所有接口通用）

0.1 服务器域名

域名 用途
http://parent-manage.readboy.com 主接口域（HTTP 明文！）
https://parentadmin.readboy.com 管理域（HTTPS，解绑/控制App上传等）

⚠️ 注意：绝大多数接口是 HTTP 明文，只有解绑、miPush 上传等少数走 HTTPS。

0.2 请求公共参数（几乎所有接口都有）

参数 含义 来源
signature MD5 签名 MD5(秒时间戳 + APPSECRET + MD5(APP_ID2))
imei 设备序列号 Util.getSerial()
timestamp 毫秒时间戳 System.currentTimeMillis()
app_id 应用 ID 固定 parent-manage

⚠️ 签名用秒（10位），而 timestamp 请求参数传毫秒（13位）。两者单位不同，不要搞混！
注意：签名不含任何设备密钥，纯靠硬编码的 APPSECRET。任何人反编译 APK 都能伪造签名 → 身份鉴别形同虚设。

0.3 响应公共结构（OnlineResponseBean）

大多数接口响应是统一 JSON 外壳：

字段 类型 含义
status int 1 = 成功；0 = 业务失败（看 errno）
errno int 错误码（见 0.4）
errmsg string 错误描述
timestamp string 服务器时间戳

⚠️ 例外：jpush/content 不使用此外壳，它返回 {"status":1,"data":{...}}（无 errno/errmsg，配置全在 data 内）——详见 1.1。其它接口若返回 data 对象也直接挂在外壳同级（如 {status, errno, errmsg, timestamp, data:{...}}）。

0.4 已知错误码（errno）

errno 十六进制 含义
7018 0x1B5A 时间戳错误（客户端只打日志，不重试）
7214 0x1C2E RID 或列表不存在

0.5 请求方式

  • Volley 系列：GET/POST 参数走 getParams()（POST body 或 URL query），部分走 Header
  • OkHttp 系列：okHttpPost(url, map, callback)
  • 认证头（部分接口）：Authentication: 4G:<MD5签名>

一、配置拉取类（云端 → 平板）

1.1 全量配置拉取 ★核心接口

请求参数：

参数 值
signature getSign2()
imei 设备序列号
timestamp 毫秒时间戳（13位，注意与签名用秒不同）
app_id parent-manage
push_type 推送类型
get_all 0=轮询(只返回4个版本号)；1/2/3=全量配置

get_all=0（3秒轮询）→ 只返回 applet_config_version/applet_rule_version/ask_model_version/forbidden_version 4个版本号
get_all=1/2/3（开机/网络变化/密码变化/应用更新）→ 完整配置

响应 JSON ⚠️（实测修正：所有字段在 data 对象内，不在顶层！）

微信/QQ 轻应用特判：control_list 中 com.tencent.mm / com.tencent.mobileqq 有独立的 status=1 时执行 BrandBlockUtil.setBlockState 特殊处理（微信小程序），勿遗漏。

control_list 元素字段（实测 AppControlStatus bean）：

字段 类型 说明
Id int 记录 ID
imei string 设备序列号
pack_name string 包名
status int 管控状态（见下方映射）
operated_at string 操作时间（⚠️ 不是 operated）
app_time List 应用时段限制
temp_use object null
extra int 附加
system_mode int 系统模式
anti_addiction object null

control_list 的 status → 本地 disabled_state 映射（⚠️ 实测修正：status=2 也禁用）：

云端 status 本地 disabled_state 含义
1 0 正常（允许）
0 1 禁用
2 1 禁用（删减状态，文档此前遗漏）

即：disabled_state = (status == 1) ? 0 : 1（status={0,2} 都禁用！）

⚠️ 致命陷阱：空 control_list ≠ 放行！

实测代码 GetOnlineAppResponse2：if (list != null && list.size() > 0) 才进入处理循环，空数组 [] 什么都不做，本地 install_app_list.disabled_state 保持不变。已禁用的应用不会自动恢复。必须显式返回包含该应用且 status=1 的记录才能解除禁用。

客户端处理（覆盖本地）：

  • control_list → 逐项 update install_app_list（disabled_state/app_state/upload_state/network_app_state 全覆盖）
  • password → update/add/delete user_info（无条件覆盖本地密码）
  • allow_input_pwd → 写 SharedPreferences no_allow_input_pwd + Settings.Global rby_enable_start_machine_by_password
  • 其余各 xxx.status → 对应各控制开关

⚠️ 响应外壳注意：jpush/content 实测返回 {"status":1,"data":{...}}，没有 errno/errmsg 字段（Gson 解析多余字段忽略、缺失字段无害）。

六、模拟服务端要点（如果厂商跑路后自建）

  1. 域名解析劫持：改平板 hosts，把 parent-manage.readboy.com 指向自己的服务器（需 root 或系统权限）
  2. 最少实现 3 个接口：
    • /api/v1/jpush/content（下发配置）
    • /api/v1/heart_beat（回复 {"status":1} 保持在线）
    • /api/v1/machine/get_active_status（回复 {"data":{"activated":1}}）
  3. 响应格式：所有接口都必须返回 {status, ...} 外壳；jpush/content 的配置字段必须在 data 对象内，否则客户端解析失败、永不应用配置
  4. 签名验证：客户端不验证服务器响应签名（响应无签名），但请求必须带正确签名（signature 用硬编码密钥可算）
  5. ⚠️ 空 control_list 不放行！ 见下方正确放行配置——必须显式列出每个已禁用应用并给 status=1，空列表只会什么都不做
  6. 版本号机制（jpush/content 响应里）：forbidden_version/ask_model_version/applet_config_version 一旦高于本地版本，会触发对应功能重传（0x29 USB状态/0x49 作业模型/0x3e 小程序配置）
