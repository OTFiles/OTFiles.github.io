〇、公共约定（所有接口通用）

0.2 请求公共参数（几乎所有接口都有）

参数 含义 来源
signature MD5 签名 MD5(秒时间戳 + APPSECRET + MD5(APP_ID2))
imei 设备序列号 Util.getSerial()
timestamp 秒时间戳（10位） System.currentTimeMillis() / 1000
app_id 应用 ID 固定 parent-manage

⚠️ 签名和 timestamp 参数都用秒（10位）（反编译 BaseResponseBean.getTimestamp() 确认 = timestamp/1000）。早期文档曾误记为毫秒，已修正。
⚠️ 签名不含任何设备密钥，纯靠硬编码的 APPSECRET。任何人反编译 APK 都能伪造签名 → 身份鉴别形同虚设。
📱 api-super 域不使用此签名，改用 getSn（见 7.1）。

0.3 响应公共结构（OnlineResponseBean）

大多数接口响应是统一 JSON 外壳：

字段 类型 含义
status int 1 = 成功；0 = 业务失败（看 errno）
errno int 错误码（见 0.4）
errmsg string 错误描述
timestamp string 服务器时间戳

⚠️ 例外：jpush/content 不使用此外壳，它返回 {"status":1,"data":{...}}（无 errno/errmsg，配置全在 data 内）——详见 1.1。其它接口若返回 data 对象也直接挂在外壳同级（如 {status, errno, errmsg, timestamp, data:{...}}）。

0.4 已知错误码（errno）

errno 十六进制 含义
7018 0x1B5A 时间戳错误（客户端只打日志，不重试）
7214 0x1C2E RID 或列表不存在

0.5 请求方式

  • Volley 系列：GET/POST 参数走 getParams()（POST body 或 URL query），部分走 Header
  • OkHttp 系列：okHttpPost(url, map, callback)
  • 认证头（部分接口）：Authentication: 4G:<MD5签名>

六、模拟服务端要点（如果厂商跑路后自建）

  1. 域名解析劫持：改平板 hosts，把 parent-manage.readboy.com 指向自己的服务器（需 root 或系统权限）
  2. 最少实现 3 个接口：
    • /api/v1/jpush/content（下发配置）
    • /api/v1/heart_beat（回复 {"status":1} 保持在线）
    • /api/v1/machine/get_active_status（回复 {"data":{"activated":1}}）
  3. 响应格式：所有接口都必须返回 {status, ...} 外壳；jpush/content 的配置字段必须在 data 对象内，否则客户端解析失败、永不应用配置
  4. 签名验证：客户端不验证服务器响应签名（响应无签名），但请求必须带正确签名（signature 用硬编码密钥可算）
  5. ⚠️ 空 control_list 不放行！ 见下方正确放行配置——必须显式列出每个已禁用应用并给 status=1，空列表只会什么都不做
  6. 版本号机制（jpush/content 响应里）：forbidden_version/ask_model_version/applet_config_version 一旦高于本地版本，会触发对应功能重传（0x29 USB状态/0x49 作业模型/0x3e 小程序配置）

七、手机端家长助手（家长 App）api-super 域接口 ★新发现

7.1 签名算法（Util.smali getSn）

  • 已登录：arg3 = MD5(uid8)（uid 为家长账号 uid）
  • 登录时：arg3 = MD5(PACKAGE)，uid8 = "00000000"

7.2 认证流程（token 强制）

响应（MobileRegisterResponse）：

登录后所有请求带 **sn=getSn(uid8, ts, MD5(uid8)) + token=access_token**。

⚠️ 实测（2026-08）：不带 token 请求时，签名验证通过后返回 {"errmsg":"token无效","errno":8002}——token 无法绕过，必须登录。签名参数名是 sn（不是 signature），传平板端签名返回 7001「签名不能为空」，传错 uid 返回 7003「签名无效」。

11.3 ⭐获取完整刷机包/增量包的方法（可直接复现）

  1. 标准获取：用真机参数 POST update.php（无鉴权），从响应 data.packageUrl 拿到直链（HTTP 明文，appdata.readboy.com 实为阿里云 OSS 桶 appmall.oss-cn-shenzhen），同一响应还给出 ConfigXml 配置文件地址。

    实测把 fingerprint 换成 forge_full_package、甚至换成任意字符串，服务端响应完全一致，仍是增量包（G90-20160611-20160630.zip，18.5MB，command=update_with_inc_ota）。

    请求 display 服务端回应

    G90_19700101 / zzz（库里不存在） no update available
