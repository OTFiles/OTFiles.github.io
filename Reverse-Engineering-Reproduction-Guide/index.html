逆向复现指南：如何自行验证家长管理接口手册中的每条结论（apktool / smali / 抓包）

逆向复现指南

这是《家长管理生态接口手册》系列的配套方法篇。
手册正文里的 smali 行号、类名、硬编码常量、抓包样本都可以用下面这套流程独立验证——
原文分析的 APK 与反编译目录不会被长期保存，所以方法必须固化下来。

一、复现前提：拿到样本

样本 包名 用途
家长管理 v6.2.8 com.readboy.parentmanager 平板端全部接口、Provider 漏洞、解绑/配置机制
家长助手 com.readboy.rbmanager 手机端 api-super 域
应用商店 cn.dream.android.appstore 商店接口、安装管控判定
系统设置 Settings.apk（系统分区） USB 调试显示条件、通知黑名单、EWC 认证
DreamUpdate com.dream.ota.update OTA 查包/下载链路
personalsetting com.readboy.personalsetting 个人设置 API、native 签名
计算器 com.dream.calculator 工厂模式后门
killapp com.readboy.killapp 查杀/禁通知/深度隐藏列表、键位语义

取样本的常规方式：adb shell pm path <包名> 找到路径后 adb pull；系统应用需 adb root 后直接拉取。

二、反编译

反编译后会得到 smali/、smali_classes2/（多 dex 时按 classes2.dex 顺序命名）。同一个类只会在其中一个目录里。

四、定位常量与字符串

五、关于「行号」

手册里写的「GetOnlineAppResponse2 5362 行起」这类行号，指 apktool 默认输出下该 smali 文件的行号。
换 apktool 版本、或改用 apkeditor，行号会有偏移。按内容搜（相邻字符串或方法名）比按行号可靠。

六、字节码阅读要点（判断”为什么这么写”）

smali 片段 含义
const-wide/16 v2, 0x3e8 + div-long/2addr p1, v2 除以 1000（毫秒→秒），签名/时间戳处常见
.field protected static final ERROR_TIME:I = 0x1b5a 常量 7002
invoke-static {p0}, Lcom/readboy/parentmanager/core/utils/MD5Util;->GetMD5Code(Ljava/lang/String;)Ljava/lang/String; 调 MD5 工具类
if-ne v1, v4, :cond_1 不相等则跳转（if-ne = not equal）
const/4 p0, 0x0 + return-object p0 返回 null
iget-wide v0, p0, ...->timestamp:J 读 long 字段
invoke-virtual {v1, p1, p2}, Ljava/lang/StringBuilder;->append(J)Ljava/lang/StringBuilder; 数字拼进字符串

关键技巧：遇到「时间戳是秒还是毫秒」这类问题，必须同时看两处——
① getXxx() 里有没有 /1000；② 调用方传进来的是 currentTimeMillis() 还是已除过的值。
只看一处必错（本项目曾因此把 timestamp 记成 13 位）。

七、抓包验证

家长管理走 HTTP 明文、无双向校验，直接看得到 body：

  • PC：mitmproxy / Charles + 设备设代理
  • 设备：抓包类应用（需 root 或 VPN 方式）
  • 签名可自行按 手册 0.2 的算法计算，用来构造请求（不只是被动看）

八、复现检查清单

  • 反编译出 smali*/ 目录
  • 用「三、定位类」的路径找到目标类
  • 用「四、定位常量」搜到手册引用的字符串/常量
  • 对时间戳秒/毫秒这类易错点，同时看 getXxx() 的除法与调用方传入值
  • 用抓包核对真实请求参数位数、字段位置（data 内 vs 顶层）
  • 需要动态行为时，adb logcat 过滤包名看设备自己的日志
  • 核对 SharedPreferences 文件名与 key（很多”改了不生效”是改错了存储层）

九、常见坑

现象 原因
按行号找不到代码 apktool 版本不同导致偏移 → 改按内容搜
grep 搜不到中文 smali 里中文以 UTF-8 原样存在，但有的终端 locale 不对 → 用 grep -a
改了数据库不生效 应用把值缓存在内存/SharedPreferences，且下次全量拉取会覆盖（见解绑专文 8.4.1）
already latest 当成失败 这是服务端定论（机型匹配成功、无更新包），不是参数错
反编译后没有 smali_classes2 该 APK 只有一个 dex，全部类都在 smali/
