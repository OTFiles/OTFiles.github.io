④ 系统更新 DreamUpdate（OTA）与系统组件

本分册对应原手册 第十一、十二章与附录。

第十一章是全套材料里最”可直接用”的一章：ota.readboy.com/update.php 无任何鉴权/签名/token，HTTP 明文，

十一、系统更新 DreamUpdate（com.dream.ota.update）：完整刷机包/增量包获取方法 ★2026-09 新增

来源：DreamUpdate.apk 反编译 + 2026-09-26 对 ota.readboy.com 的实测验证。⚠️ 整个 OTA 体系无任何鉴权/签名/token，HTTP 明文，任何人 POST 设备参数即可拿到对应机型的刷机包直链。（管理后台在 http://ota.readboy.com/index.php?s=/Admin/Public/login，机型库即在那套「安装包管理系统」里；未做任何越权访问。）

11.1 检查更新接口（核心）

请求参数（Form，无签名；顺序与官方 CheckingTask.sendPost() 一致）：

# 参数 取值来源 说明
1 updating_apk_version OTA 应用版本名
2 model ro.product.model ★匹配键
3 brand ro.product.brand 不参与匹配
4 name ro.product.name 不参与匹配（实测改掉也能命中）
5 device ro.product.device 不参与匹配
6 board ro.product.board ★匹配键
7 mac WifiManager.connectionInfo.macAddress 不参与匹配
8 firmware ro.product.firmware 取不到即空串
9 android ro.build.version.release ★匹配键
10 time ro.build.date.utc
11 builder ro.build.user
12 fingerprint ro.build.fingerprint ⚠️ 实测既不参与机型匹配，也不决定增量/完整包
13 display ro.fota.version ★必填：当前固件版本号；空值直接回 no firmware version param
14 hard ro.build.version.hard 原值，取不到即空串（不要拿 Build.HARDWARE 顶替）
15 serial Build.getSerial() 不参与匹配
16 chipset ro.build.chipset ★★匹配键；空或 unknown → 归一为空串
17 id Preferences.getID() ⚠️ 恒为 1000（见下）
18 debug 通道 0/1/2 ⚠️ 通道是这个参数，不是 id
19 is_log 固定 1
20 ip NetworkProber.getLocalIpAddress() 本机局域网 IP
21~23 uid / username / realname 读书郎账号 未登录时为空串

三个最容易写错的点（更正）：

  1. id 不是通道号。Preferences.getID() 实现：getInt("ID", 1001) → 若为 1001 则算一个随机数写回 → **但最终无条件 return 1000**（smali：const/16 v0, 0x3e8 / return v0）。所以官方每次发的都是 id=1000。
  2. 通道由 debug 承载：默认 "0"；CardManager.isPublicBetaTest() → "2"（公测）；CardManager.isTest(ctx) → "1"（测试）。
    实测同一机型：debug=0 → update found；debug=1/2 → no update available（两个测试通道库里没有该包）。
  3. **chipset 取自 ro.build.chipset**（/sys/devices/soc0/soc_id 只用于三个机型的后缀特判）：
    • Readboy_C12 + soc_id 294 → chipset += "_MSM8937"
    • Readboy_G500X + soc_id 295 → chipset += "_APQ8037"
    • Readboy_V100 + soc_id 313 → chipset += "_msm8940"

测试卡模式（CardManager.isTest）会把参数整体伪造成一组固定值（工厂测试卡走测试通道），可直接照抄复现：
model=Readboy_G90、board=msm8916、android=4.4.4、display=G90_20160611、chipset=AllWinner_8916_G90_01、debug=1。

响应（实测真实结构）：

status 共四种（实测）：

status 含义
update found 命中，含 url（ConfigXml 地址）+ data.packageUrl（直链）
model not found 机型库四元组 (model, board, android, chipset) 未匹配（见 11.6）
no update available 机型匹配成功，但按当前 display 没有可下发的包
no firmware version param display 为空

客户端兼容两种形态：data.packageUrl 直用；若没有 data（老服务端）则只回 {"url": "..."}，需再下载 XML 解析：

⚠️ command 必须 = update_with_inc_ota（增量通道）。另外 ConfigXml 路径本身就泄露了**服务端规范机型名 = <model>_<chipset>**（如 Readboy_G90_AllWinner_8916_G90_01）。

11.2 下载与安装链路

11.3 ⭐获取完整刷机包/增量包的方法（可直接复现）

  1. 标准获取：用真机参数 POST update.php（无鉴权），从响应 data.packageUrl 拿到直链（HTTP 明文，appdata.readboy.com 实为阿里云 OSS 桶 appmall.oss-cn-shenzhen），同一响应还给出 ConfigXml 配置文件地址。

  2. ⚠️ 更正（2026-09-26 实测）：原稿“传一个服务端不认识的 fingerprint 可强制回退下发完整包”不成立。
    实测把 fingerprint 换成 forge_full_package、甚至换成任意字符串，服务端响应完全一致，仍是增量包（G90-20160611-20160630.zip，18.5MB，command=update_with_inc_ota）。
    👉 包类型由服务端机型库条目决定，客户端无法用参数干预。

  3. 能拿到哪个包完全取决于 display（当前版本号）——实测同一机型：

    请求 display 服务端回应
    G90_20160611（真实当前版本） G90-20160611-20160630.zip（Version = G90_20160630）
    G90_20160630 G90-20160630-20160714.zip（Version = G90_20160714）
    G90_19700101 / zzz（库里不存在） no update available
    ""（空） no firmware version param

    即：只能拿到“你当前版本 → 服务端记录的下一个版本”这一步增量包。想要全量包，除非机型库里存在以该版本为基线的全量条目（G90 库里全是增量）。

  4. 通道：debug=1（测试）/ debug=2（公测）若库里有包即可拿到未推送固件（G90 实测这两个通道返回 no update available）。

  5. “必定命中”的样例：直接照拄 11.1 末尾那组 G90 测试卡参数（服务端确定存在该机型）。

  6. 本地刷机（不依赖服务器）：DreamUpdate 支持从 TF 卡/外置 SD/USB 存储（UpdaterInfo.recovery_sdcard/recovery_extsd/recovery_usb）读取升级包；DownloadActivity 扫描存储根目录的 ota.zip（“根目录未发现ota.zip文件”）→ 把任意官方 zip 改名 ota.zip 放根目录即可本地升级（还能绕过服务器检查）。

11.4 辅助接口

接口 用途
GET http://ota.readboy.com/adddown.php?id=<id> 下载计数上报（data.id）
GET http://ota.readboy.com/space.php?model=..&display=..&android=..&board=.. 设备分区/空间统计（fetchSpace，启动时上报）。⚠️ 函数签名里还有第 5 个 chipset 参数，但拼接 URL 时只用 4 个（model/display/android/board）；缺 model 回 no model param，缺 display 回 no firmware version param

11.5 备注

  • 请求头无任何认证，参数空格转 %20，响应 UTF-8。
  • OtaUpgradeUtils.checkIncVersion(fingerprint, product)（校验本机 FINGERPRINT+DEVICE/PRODUCT 是否匹配升级包基线）在本 APK 内无调用者（死代码）——包类型选择完全在服务端完成。
  • 下载用系统 DownloadManager（XML）+ 自研多线程下载器（zip 本体）双套实现。

11.6 服务端机型库匹配规则（实测逆向）★关键

机型库的查找键是 四元组 (model, board, android, chipset)，必须精确相等，其余参数一概不看。
用 App 自己内置的 G90 参数做对照实验（服务端确定存在该机型）：

实验 结果
Readboy_G90 + board=msm8916 + android=4.4.4 + chipset=AllWinner_8916_G90_01 ✅ update found（返回包地址）
chipset=foobar_chipset（乱值） ❌ model not found
chipset=（空） ❌ model not found
仅改 board=msm8998 ❌ model not found
仅改 android=9 ❌ model not found
仅改 name/device=msm8998 ✅ 仍命中（→ 不参与匹配）
改 display=202308161825、serial、mac、id、fingerprint、hard ✅ 均仍命中（→ 不参与匹配）

补充观察：

  • chipset 字符串的官方格式为 <方案商>_<SoC编码>_<机型>_<版本>（G90 的是 AllWinner_8916_G90_01），例如对 Qualcomm msm8998 机型就有可能是 Qualcomm_8998_XXX_01；但这个值只能从设备自身的 ro.build.chipset 取得，库内无通配/模糊匹配（model=Readboy_C1% / Readboy_ 均回 model not found）。
  • 机型库无法枚举：http://ota.readboy.com/ConfigXml/ 返回 403（目录存在但禁列目录，单文件 200，不存在的路径 404）；OSS 桶 appdata.readboy.com 的 ListObjects 被策略拒绝（AccessDenied）；index.php 是 ThinkPHP 后台登录页。因此实际查询应当直接用设备自身属性发请求。
  • 为什么之前“拿不到包”：旧实现把 chipset 填成了 soc_id（如 292）且把通道号发到了 id；chipset 一错，无论其它参数多正确都只会得到 model not found。

实测样本二：读书郎 C18（Android 9 / msm8998） —— 说明「匹配成功」和「有包可下」是两件事：

设备真实属性（getprop 全量快照）：

属性 值
ro.product.model Readboy_C18
ro.product.brand readboy
ro.product.name / device / board msm8998
ro.build.version.release 9
ro.build.chipset QCOM_8998_android9_C18
ro.build.display.id 202308161825
ro.build.version.soft C18_202308161825
ro.boot.soc_id 292（★不能拿来当 chipset）
ro.build.fingerprint readboy/msm8998/msm8998:9/PKQ1.190908.001/202308161825:user/release-keys

用上面四元组 (Readboy_C18, msm8998, 9, QCOM_8998_android9_C18) 请求，服务端返回 **{"status":"already latest"}**：

  • ✅ 匹配成功（若 chipset 错会回 model not found）——证明 chipset 取 ro.build.chipset 是对的；
  • ❌ 但 C18 没有任何可下发的新包。换更早的 display（逐天递减试了 20230815/14/13/12）全部回 **no update available**（= 该版本无基线包）；
  • ❌ 直接探目录 http://ota.readboy.com/ConfigXml/Readboy_C18_QCOM_8998_android9_C18/ → 404（= 服务端从未上传过该机型的 ConfigXml）；对照组 G90 的目录 → 403（= 目录存在、仅禁列目录）。

结论：C18 的固件只能走厂商售后/产线渠道，OTA 接口这条路已确认无包。already latest / no update available 都是服务端的定论，继续换参数探测没有意义——只有 model not found 才说明参数不对。

  • 本项目的公开实现（Kotlin/MD3，带自动参数探测）：github.com/OTFiles/ZaralynOTA。

12.3 权限/行为注意点

  • 应用内置 root 检测（遍历 /system/bin/su、/system/xbin/su、/sbin/su、/data/local/su 等路径）。
  • 集成人脸识别引擎（libSeetaFace*，SeetaFace600 系列）——/face/login、/face/bind 接口配套。
  • 点读笔绑定/数据上报（/scan_pen/*：add/get/quit_pen_bind、send_scan_data、get_device_bind）。
