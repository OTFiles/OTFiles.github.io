③ 应用商店（cn.dream.android.appstore）与系统设置（Settings.apk）

本分册对应原手册 第八、九、十章。

三条主线：

  1. 应用商店：它不只是”下载应用”，还会以 app-store 身份去调家长管理域的接口（这是安装管控的关键一环），
    另有主域 g-apkstore.strongwind.cn 的 57 个接口、学分/商城/关怀等周边域名。
  2. 隐藏的 USB 调试：设置里的「USB 调试」被永久隐藏，能否显示由家长管理的 un_mall_app_state 表决定（= 云端 allow_unknown_app），
    另有 _wfad_ WiFi 高级选项暗门、工厂/产线逻辑。这是”为什么开发者选项里没有 USB 调试”的完整答案。
  3. Settings 自身的隐藏接口：EWC 设备认证、屏幕/LCD 上报、SN 回源、通知黑名单、内网产线预装 API、摄像头配置、自更新；
    以及 killapp 实锤的四张动态列表（查杀/禁通知/深度隐藏/键位）。

八、应用商店（cn.dream.android.appstore）网络接口 ★2026-09 新增

来源：读书郎应用商店 APK 反编译（Retrofit + OkHttp + Gson）。
应用商店是安装限制体系的客户端执行者：家长管理负责下发策略，但实际拦截下载/安装动作的是应用商店与系统 Settings。
本章含两套接口：① 应用商店以独立 app-store 身份调用家长管理域的 4 个接口（与平板端家长管理同一套服务端！）；② 商店主域 g-apkstore.strongwind.cn 的 57 个接口。

8.1 应用商店 → 家长管理域（app-store 身份）⭐重点

认证体系（与平板端同构但密钥不同）：

⚠️ 安全观察：服务端同时接受两套身份（parent-manage / app-store），各自密钥都硬编码在各自 APK 里，拿到任一密钥即可伪造对应身份的请求。商店请求走 HTTPS，抓包需解密。

8.1.1 下载等级查询

响应（ControlStateBean，⚠️ 与第五章同一接口，但商店端解析字段更多）：

字段 类型 商店端用途
status int 1 才使用 data；否则回退本地 provider
data.download_level int 下载等级 0/1/2/3（见 8.4）
data.password string 家长密码（8.1.2 回源用）
8.1.2 家长密码回源

响应：同 ControlStateBean。商店本地 user_info 表查不到家长密码时用此接口回源：data.password 非空 → 视作「受限模式」（进入下载等级判定）；空 → 放行。

8.1.3 申请解锁（向手机家长端发送下载请求）⭐平板端没有的接口

FormBody 参数：

参数 值
app_id app-store
timestamp 10位秒
signature MD5(秒+appsec+MD5(app-store))
serial 设备序列号
pack_name 被拦截的应用包名
firmware 机型（Constants.model）
firmwareversion 固件版本

响应：仅检查 HTTP 2xx，不解析 body（UIHandler 0xc8/0xc9）：

  • HTTP 成功 → Toast「已向手机家长端发送下载请求」（手机家长 App 收到后处理）
  • 失败 → Toast「向手机家长端发送下载请求失败」
8.1.4 更新包列表上报

FormBody 参数： app_id + timestamp + signature + imei + pack_names（包名列表字符串）。回调仅记日志，失败不重试。

8.2 商店主域 g-apkstore.strongwind.cn（57 个接口）

基础配置：

全局拦截器（CallManager$HeaderInterceptor，每个请求自动附加）：

  • Query 参数：firmware(机型)、firmwareversion、storeversion(商店版本码)、systemversion(SDK_INT)、device(机型)、chipset、isParent(是否家长模式)、innername(内部型号)、hardware(product)

8.4 安装管控判定全流程（点击下载按钮）⭐

关键常量：

常量 值 含义
新版阈值 versionCode ≥ 181225001 (0xacd4629) fetchParantLimit 判定「新版家长管理」
levelId 判定阈值 versionCode ≥ 200608001 (0xbf50901) canParentDownload 用 levelId 比较；低于则用分类 ID 判定（老版）

⚠️ 两个阈值不一致（181225001 vs 200608001），推测对应家长管理不同中间版本的行为差异。

九、设置中隐藏的 USB 调试选项：显示条件全链路分析 ★2026-09 新增

来源：系统 Settings.apk（Android 10 定制）反编译。结论先行：USB 调试选项是否显示，由家长管理的 un_mall_app_state 表决定（即云端 allow_unknown_app 开关）。

9.1 标准「USB 调试」被永久隐藏

Android 原生的 enable_adb（「USB 调试」开关，AdbPreferenceController）在固件里被硬编码隐藏：

用户在开发者选项里能看到的唯一 ADB 开关是读书郎定制项（布局 development_settings_part.xml，由 DevelopmentSettingsDashboardFragmentPart 加载）：

key 标题 摘要
enable_usb_connect_pc 连接电脑设备允许ADB调试 授权允许USB连接电脑设备，开启ADB调试

9.2 显示条件（ReadboyUsbCnnPreferenceController）⭐核心

USB 调试选项显示 ⟺ 同时满足：

# 条件 说明
1 un_mall_app_state.state == 1 通过家长管理 AppContentProvider 查询；空表/未装家长管理/异常 → 一律不显示
2 ro.readboy.control_usb_debug ≠ 0 固件属性，出厂未设置（=-1）即满足；仅显式设 0 的机型才隐藏
3 当前是主用户（isAdminUser） 副用户/访客不显示

⚠️ 该查询只在控制器构造时执行一次并缓存——进入开发者选项页面的那一次决定开关是否出现；退出重进才会重新判定。

9.3 与云端配置的联动链（谁写 un_mall_app_state）⭐

un_mall_app_state.state 的写入方（家长管理 6.2.8 GetOnlineAppResponse2 反编译）：

完整链路：

实测印证（见第一章实测抓包）：该设备 "allow_unknown_app": {"status": 0} → state=0 → USB 调试选项不显示。

⚠️ 新版家长管理（6.2.8+）实测陷阱：若云端未下发 allow_unknown_app 配置，该表可能为空（此前逆向 ZaralynSetting 修复时确认）→ 查询无行 → state=0 → 选项永不显示，即便家长已在新版机制（install_app_list）里放行。
💡 用 ZaralynSetting 打开「全局安装限制」（允许）会同时 upsert un_mall_app_state.state=1 → 退出重进开发者选项后 USB 调试开关恢复显示。

9.4 开关状态与写入行为

显示状态：isUsbConnectPcEnabled() = Settings.Global adb_enabled==1 且 readboy_developer_enabled_adb==1（两个都开才勾选）

切换写入（writeUsbCnnPcEnableSetting）：同步写 adb_enabled + readboy_developer_enabled_adb 两个 Global 设置，并 notifyChange + 发本地广播 com.android.settingslib.development.AbstractEnableAdbController.ENABLE_ADB_STATE_CHANGED。

可交互条件：仅当开发者选项页顶部总开关（SwitchBar）打开时 setEnabled(true)（isReadboyAdbEnable = isDevelopmentRootSwitchOn）；ADB 被系统关闭时（onAdbSettingChanged）自动取消勾选。

9.5 开发者选项页面本身的门槛

进入页面（关于平板→连点版本号 7 次，标准 AOSP 流程，需主用户）后，onResume 触发 runCheckParentPassword(0x271a)：

场景 行为
非 user 编译（userdebug/eng 固件） 自动通过
EBagPad 机型 拉起 cn.dream.ebag.action.SETTING_TEACHER_CHECK 教师验证

9.8 结论速查表

环节 条件

让开关显示的可行途径：

  1. 手机家长端打开「允许安装未知应用」（allow_unknown_app=1）→ 云端同步后 state=1
  2. 用 ZaralynSetting「全局安装限制」设为允许（会 upsert un_mall_app_state=1）→ 退出重进开发者选项
  3. 直接用 root/adb 写 content://com.readboy.parentmanager.AppContentProvider/un_mall_app_state（state=1）

10.5 通知黑名单（版本化拉取）⭐

这不是单纯的”黑名单”，而是一份多用途云端应用管控配置，由 PowerOffKeeperService 随机延迟轮询拉取（同名下载逻辑也存在于独立系统应用 com.readboy.killapp，两份各存各的）。

响应（版本化 JSON）：

存储： data.latest_version > 本地 fwq_cfg_version 才更新；内容存 SharedPreferences（fwq_cfg_data/fwq_cfg_version/fwq_cfg_md5/fwq_cfg_last_update_time）。

两个已实锤的用途：

  1. 深度休眠隐藏应用（键 "4"，Settings 消费）：AppInfoDashboardFragment.setActivityDisplayByComponentName —— 隐藏应用时若包名在 "4" 列表中，除了 disable 桌面入口 Activity 隐藏图标，还连带 setServiceEnabledByPkgName + setReceiversEnabledByPkgName 禁用该包全部 Service 和广播接收器 → 应用完全休眠：不跑后台、收不到广播、发不出通知。开机时 SettingsBootCompletedReceiver 逐一恢复隐藏状态。
  2. 后台查杀与禁通知（键 "1"/"2"/"3"，com.readboy.killapp 消费）：FwqConfigureIntentService.refreshSystemFilterList 解析：
键 存入 实际动作（已实锤）
"1" MyApplication.mSystemClosedNotifycationAppPkgNames resetAllNeedCloseNotifycationApp() 遍历桌面全部应用，命中列表的包调 INotificationManager.setNotificationsEnabledForPackage(pkg, uid, false) → 系统级禁用该应用全部通知（设置里显示”已关闭”）
"2" DetectOverCpuFrequencyService.killApp needKill() 判定：不在强制白名单/用户白名单/最近启动者名单 → ActivityManager.killBackgroundProcesses() + forceStopPackage() 强杀
"3" DetectOverCpuFrequencyService.mForceThridWhiteListPkgNameAll 强制免杀白名单（云端下发，用户不可见不可改，优先级最高）
"4" Settings 消费（见上） 深度休眠隐藏
Prop 数组 按包名+安卓版本（models_and7~`models_and12）+机型过滤，返回 {code, delay, content}` —— 查杀延迟/提示文案策略，供 killapp 白名单弹窗等消费
  1. 跨应用共享配置：SettingsSharedContentProvider（authority com.android.settings_rby_shared_data，call 方法分发）：
    • com.readboy.killapp_shareddata → 返回整个 fwq_cfg_data JSON
    • checkDelayTimeInFwqCfgByPackageName(Bundle) → 入参 reqPkgName+filterPkgNames+reqMdExtraName，在 Prop 数组里过滤（与上表 Prop 同逻辑）
    • 另有 helpRemoveTaskFromRecentAppList（从最近任务移除）、helpAddPowerSaveWhitelistApp（加入省电白名单）等供 killapp 反向调用的辅助接口

跨应用读取机制： AppInfoDashboardFragment.getKillappSharedPreferencesData() 用 createPackageContext("com.readboy.killapp") 直接读 killapp 的 SharedPreferences（同 system uid 才可行）。killapp 自己也独立拉取同一 URL 存一份（FwqConfigureIntentService，带同一套 MD5 版本化更新判断）；Settings 下载的那份在 Settings 内反而无人读内容（仅版本号用于更新判断），疑似 copy-paste 冗余。

⚠️ killapp 侧确认：该配置是云端可随时增删的免杀/强杀/禁通知/深度隐藏四张动态列表，无需发版即可改变任意应用的查杀策略。
